# 今週の献立（プロトタイプ）

週間献立・レシピ・**複数料理の一括調理工程の最適化**・在庫／買い物／作り置き・セブン-イレブン昼食・健康ログを一体化した、個人向け食生活管理Webアプリのプロトタイプです。

```bash
npm install
npm run dev      # http://localhost:5188
npm test         # エンジン・連動ロジックのテスト（19件）
npm run build    # 本番ビルド（dist/）
```

## 画面
| パス | 画面 | 主な操作 |
|---|---|---|
| `/` | ホーム | 今日の夕食と準備方法、食べたを記録、昼食候補、期限間近、今週の食費、栄養、体重 |
| `/plan` | 週間献立 | AI提案・再生成、料理の差し替え、ドラッグ／矢印で曜日移動、作り置き⇔当日調理、確定 |
| `/recipes` `/recipes/:id` | レシピ図鑑 | 絞り込み、お気に入り、AIでレシピ作成、材料・分量・工程・器具・依存関係の編集 |
| `/cook` | 一括調理ナビ | 工程タイムライン、現在／次の工程、タイマー、スキップ、中断・再開、完了で在庫更新 |
| `/pantry` | 食材・買い物 | 在庫（スワイプ削除・取り消し）、売場別買い物リスト・価格入力・予算消化、作り置き |
| `/lunch` | セブンの昼食 | 3パターン提案と理由、記録・置き換え、お気に入り、履歴、商品コード／カメラ読み取り |
| `/health` | 健康 | 目標の根拠、PFC・微量栄養素、たんぱく質推移、体重（日次＋7日平均）、生活習慣、食費 |
| `/settings` | 設定 | 予算・プロフィール、器具の数量／同時利用／洗浄方針、書き出し、初期化 |

## 構成
```
src/
  types/            ドメイン型（D1 のテーブル設計の起点）
  data/             食材・器具・レシピ・デモ商品・初期データ
  engine/           純粋関数（UI 非依存・テスト対象）
    cookPlanner.ts    一括調理スケジューラ
    planMath.ts       献立→必要食材→買い物・食費・作り置き食数
    nutrition.ts / health.ts / lunch.ts
  services/
    ai/               AIProvider インターフェース + ルールベース実装（LLM差し替え口）
    storage/          永続化アダプタ（localStorage → 将来 D1/API）
  store/            Zustand ストア。連動ユースケース（購入→在庫・支出、調理完了→在庫・作り置き…）
  pages/ components/ features/
```

## 一括調理の最適化（`engine/cookPlanner.ts`）
1. 各レシピの工程を食数分にスケール（切る=比例、炒める=フライパン1回3食、煮込み=固定）
2. **同じ食材×同じ切り方**の下処理、洗い、計量、炊飯を料理横断でまとめる（切り方が違えば別工程）
3. 衛生制約を依存関係として追加：野菜などの下処理 → 生肉・生魚 → まな板・包丁・手の洗浄 → 加熱。加熱後の肉を切る工程は洗浄後
4. 加熱後に「粗熱を取る（30分以内に20℃付近）」→「小分け（冷蔵／冷凍）」を自動付与
5. 手・コンロ・鍋・レンジ等を資源とするリストスケジューリング（クリティカルパス優先）。鍋は同じ料理の工程間で保持し、別の料理に使う前は洗浄工程を挿入。待ち時間（煮込み・レンジ）に別の手作業を割り当て
6. 器具の競合・不足、冷凍庫容量を警告として出力。1品ずつ作る場合との比較時間も算出

## 仮データと実データの区別
- 在庫の初期数量は「仮」表示（編集すると確認済みに）
- 栄養は材料の標準成分値からの**推定**、昼食は**デモ商品の表示値を模した値**として区別
- セブン-イレブンの商品・価格・コードは**架空のデモデータ**（実在の販売状況・価格ではない）
- 食材価格は いちやま湯村店 を想定した**仮の価格**
- 体重などの過去ログはサンプル（グラフに「サンプルデータを含む」表示）
- 健康目標：BMI約20・体脂肪率9%のため減量目標は設定せず、維持エネルギー＋たんぱく質 体重×1.6g

## Cloudflare への移行方針
- 静的ビルドは Cloudflare Pages（SPA フォールバック）でそのまま配信可能
- `services/storage` を D1 経由の API アダプタに差し替え（`types/` を元にテーブル化：recipes, inventory_lots, shopping_items, expenses, meal_logs, health_logs, cook_sessions ほか）
- `services/ai` に `RemoteAIProvider`（Workers の `/api/ai/*` → LLM）を実装し、返却 JSON を `buildRecipe` / `planIssues` で検証・正規化
- `engine/` は純粋関数のため Workers 上でもそのまま実行可能。画像（レシート・料理写真）は R2 を想定

## 設計で参照したスキル
- frontend-design：白基調・ハーブグリーン1色のアクセント、強調はタイムラインに集約
- ui-ux-pro-max：タッチターゲット44px、下部タブ5項目、フォーム・状態設計（推奨パレットの紫は要件の禁止事項のため不採用）
- emil-design-eng：押下時 scale(0.97)、ease-out カーブ、シートのドラッグで閉じる、reduced-motion 対応
- dataviz：チャート配色を validate_palette.js で検証（色覚多様性・コントラスト PASS）、単一軸、凡例・ツールチップ・表表示
- web-design-guidelines：取り消し可能な削除、ラベル、live region、touch-action、見出しの balance 等を反映
